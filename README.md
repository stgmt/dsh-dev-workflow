# dsh-dev-workflow

**Workflow для разработки DeepSeek Harness, умнее стандартного.**
> A battle-tested development workflow for DeepSeek Harness plugins, presets and compositions — written for AI agents (and humans) who are tired of stepping on the same rakes.

---

## Миссия

Этот репозиторий существует, чтобы **ИИ-агенты не тупили на разработке харнеса**.

Разработка под DeepSeek Harness полна неочевидных граблей: простейший cordis-плагин
может растянуться на часы итераций «почему не работает, как задумано» — не из-за
сложности API, а потому что знание лежит списком фактов, а не **порядком действий**.
Каждый раз агент наступает на грабли заново: не проверил имена тулов, забыл
host-половину при апдейте, запустил команду в confined-песочнице и час смотрел,
как она висит.

Мы это прожили сами — и вынесли в процесс. **Агент, который идёт по этому
workflow, проходит по заметкам ДО говнокода**: сначала разведка, потом код,
потом обязательная приёмка. Итерации дебага схлопываются, часы и токены
экономятся.

### Область действия

- динамические Cordis-плагины (host/client), инструменты модели, слоты и карточки, RPC;
- пресеты и композиции (`agent.cordis.yml`, локальные файлы-плагины, скилы);
- npm/git bundles (`dsh.bundle.patch`, overlay shipped-поведения без нового режима в пикере);
- отладка, аппрувы, версии, откаты;
- shell/sandbox-вызовы из кода плагина.

### Что НЕ входит

Конкретные потребители харнеса — например, рилсы. Они отдельные клиенты,
и workflow их не трогает: он про **разработку самого харнеса**, а не про то,
что на нём запускают.

## Что внутри

| Артефакт | Что это |
|---|---|
| `skills/dsh-plugin-gotchas/SKILL.md` | **Ядро.** Workflow фаз 0–6 с чек-поинтами + справочник готч. Автосрабатывает у агента (`whenToUse`), устанавливается глобально — виден во всех сессиях и пресетах |
| `template/` | Шаблон-скеффолд: готовая папка-пресет с host/client заготовкой — новый плагин стартует клоном шаблона, а не с пустого листа |
| `preset-dsh-dev/` | Пресет «всё разом»: скил + тул `tool_collision_check` (проверка имён перед регистрацией) |
| `tests/test-kit.mjs` | Тест-кит: статика всех копий + живой mount пресетов по апстрим-паттерну |
| `CHECKLIST.md` | Чек-лист приёмки («definition of done») — что проверить, прежде чем сказать «работает» |

## Что вы получите (и чего НЕ получите)

| Доставляет | Как |
|---|---|
| ✅ Workflow-скил (6 фаз, автосрабатывание) | клон в `~/.dsh/skills/` или пресет `dsh-dev` |
| ✅ Host-тулы (проверка имён и т.п.) | пресет `dsh-dev` / шаблон |
| ❌ Кастомные карточки и кнопки (client-UI) | пресет-клон их НЕ доставляет: client-модули живут только в npm-пакете с полем `dsh.client`, установленном в деплоймент |

Тулы отвечают обычным текстом — функция работает, без украшений. UI-обвязка
(карточки, панели) — отдельный дистрибутив для продуктовых плагинов, не для этого kit'а.

## Централизация скила (один канон, ноль копий)

Канон скила — **ровно один файл**: `skills/dsh-plugin-gotchas/SKILL.md` в этом репо.

**Основной путь — нативный bundle** (копии не нужны вовсе). Репо оформлен как
DSH-bundle: `package.json` → `dsh.bundle.patch` → `cordis.patch.yml`, а плагин
бандла сам регистрирует skill-провайдер на собственную папку `skills/` пакета
(`import.meta.url`). Установка одной командой:

```bash
dsh plugin --profile <имя-профиля> add github:stgmt/dsh-dev-workflow
```

Обновление — повторный `add`/`pnpm update` в профиле; слой активируется живо
(watched patch), без рестартов. Проверка слоя: `dsh --profile <имя> --dump-config`.

**Фолбэк для глобального корня** (без профилей): `scripts/sync-skills.mjs`
разливает канон по копиям (`~/.dsh/skills`, установленные пресеты, фикстура);
тест-кит синкает сам перед проверками. Правка канона + синк подхватывается
живыми сессиями хот-релоадом.

Симлинки сознательно не используем: через junction в `~/.dsh` ненадёжен
хот-релоад ватчера, а установленный пресет должен быть самодостаточной папкой
(его копируют на другие машины целиком).

## Тесты

```bash
node tests/test-kit.mjs          # путь к репо — аргументом; DSH_NM — путь к node_modules DSH
```

Перед проверками сам синкает канон во все копии. Проверяет: структуру скила,
валидность YAML-шапки (регрессия на готчу «`: ` в plain-скаляре молча ломает
frontmatter»), консистентность копий (байт-в-байт), YAML-диалект композиций
(с типом `!!js`), **живой mount** пресетов `dsh-dev` и `template-test` по
апстрим-паттерну и **доставку скила из бандла без копий** (lib/index.js +
skill-провайдер на папку пакета).

## Установка

**Bundle (рекомендуется):**

```bash
dsh plugin --profile <имя-профиля> add github:stgmt/dsh-dev-workflow
```

**Глобальный корень / пресет (без профилей):**

```bash
git clone https://github.com/stgmt/dsh-dev-workflow ~/.dsh/dsh-dev-workflow

# скил глобально (все сессии, все пресеты):
cp -r ~/.dsh/dsh-dev-workflow/skills/dsh-plugin-gotchas ~/.dsh/skills/

# опционально: пресет «всё разом» (скил + тул проверки имён):
cp -r ~/.dsh/dsh-dev-workflow/preset-dsh-dev ~/.dsh/.agent-presets/dsh-dev
```

Windows: вместо `cp -r` — `Copy-Item -Recurse`.
Обновление: `cd ~/.dsh/dsh-dev-workflow && git pull` и повторить `cp` для того, что устанавливал.

Проверка: новая сессия → скил `dsh-plugin-gotchas` в каталоге → любая задача
по разработке DSH идёт по фазам.

## Как пользоваться

**Агенту:** при любой задаче разработки DSH скил срабатывает сам. Дальше —
фазы, по порядку, с проверками после каждого шага:

0. **Скоуп** — динамика / пресет / bundle; «поставил и забыл» ≠ новый id в пикере;
1. **Разведка** — контракты через inspect-провайдеры, имена тулов, дерево слотов;
2. **Код** — plain JS, обратимость эффектов, self-report ошибок, обе половины пакета;
3. **Приёмка** — `starting` ≠ успех, сверка половин и handlers, живой вызов, уборка;
4. **Фейл** — протокол починки: диагностика → новый Package → откат;
5. **Вечное** — пресет-путь с `standingKeyFor`, только если нужен новый режим;
6. **Bundle overlay** — навесить на существующие и будущие режимы, без пункта в пикере.

**Человеку:** прочитай `CHECKLIST.md` перед ревью любого плагина — это тот же
контрольный список, которым заканчивается каждая фаза.

## Как вносить вклад (и почему это важно)

Новый инцидент → обнови канон **в тот же день**. Каждая незаписанная готча —
это часы, которые следующий агент потратит заново. Правило простое:

> Оставил грабли — запиши их в справочник и добавь чек-поинт в нужную фазу.
> Иначе ты не автор workflow, а его первый нарушитель.

Правь **только канон** (`skills/dsh-plugin-gotchas/SKILL.md`) — копии разливаются
`node scripts/sync-skills.mjs` или любым запуском тест-кита.

PR приветствуются в формате: «готча → фаза → чек-поинт → как воспроизвести».
