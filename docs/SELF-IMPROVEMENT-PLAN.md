# Самоулучшение workflow: анализ, что сделано, план автоматизации

Статус: отчёт + план. Повод: пинок пользователя «ты делаешь лютые костыли и не рефлексируешь на тему улучшения».

## 1. Анализ: почему костыли происходили

Три реальных инцидента этой сессии → какой чекпоинт отсутствовал:

| Инцидент | Что я сделал не так | Какого чекпоинта не было |
|---|---|---|
| Sync-скрипт для 6 копий скила | Построил самодельный механизм раздачи, не проверив, есть ли штатный | «Прежде строить своё — найди нативное» в Фазе 1 |
| Скил часами не срабатывал (`: ` в YAML-шапке) | Залил артефакт без парсинг-проверки шапки; нашёл только после пинка | Регрессия frontmatter в тест-ките (теперь есть) + «артефакт = проверенный парсером» |
| Не рефлексировал после срезов | Закрывал задачу без вопроса «что станет граблёй завтра? обновил ли канон?» | Обязательная фаза рефлексии перед «готово» |

Общий корень: **workflow требовал проверки результата, но не требовал ни поиска штатного
механизма до изобретения, ни ретроспективы после**. Оба пробела теперь закрыты в каноне.

## 2. Сделано (этот ход)

1. **Фаза 1, чекпоинт «Анти-костыль»**: прежде своего — докажи, что штатного нет
   (апстрим-доки, inspect, CLI `dsh plugin` / `--dump-config`).
2. **Фаза 7 — Рефлексия и самоулучшение**: ретро-чек перед «готово»; инцидент/пинок →
   готча в канон в том же ходе; финальный вопрос «обновил скил?».
3. **Тул `dsh_retro`** в бандле: печатает чек-лист рефлексии + свежесть канона
   (mtime/размер/число фаз). Дешёвый вызов = выполнимая привычка.
4. **Триггеры**: whenToUse расширен (bundle install, dsh plugin add, customSkillDirs,
   skill discovery/hot-reload, tool collisions, distribution) — больше поводов
   автосрабатывания; хот-релоад доставляет новую шапку в живые сессии сразу.
5. **Регрессия в тест-ките** (с прошлого хода): frontmatter обязан парситься как YAML,
   CRLF-толерантность, автосинк копий.

## 3. Автоматизация: что уже автоматом, что нет

Уже автоматически:
- тест-кит синкает канон и ловит структуру/шапку/копии (запуск тестов = консистентный мир);
- хот-релоад DSH доставляет правки скила в живые сессии без рестартов;
- бандл = обновление одной командой, слой подхватывается watched patch'ем.

Не автоматизировано (честно):
- **Фаза 7 — модельная дисциплина**, не железо: скил обязывает, тул снижает цену,
  но принудительного хука «конец задачи → ретро» в DSH пока не подключено.

## 4. План дальнейшей автоматизации

- **Шаг 1 — ✅ сделано:** карта событий хоста изучена (`Event.listEvents`). Найдено
  ключевое: **`agent/turn-stopping`** (serial, «ход закрывается») + `tools/result`
  (наблюдение вызовов) + `system-prompt/assemble` (водопад сборки промпта).
- **Шаг 2 — ✅ сделано (v1):** бандл слушает `tools/result` (счётчик вызовов за ход +
  факт dsh_retro) и `agent/turn-stopping`: тяжёлый ход (≥3 тулов) без ретро →
  `logger.warn` + строка в журнал. Всё в try/catch — слушатели не ломают агентов.
- **Шаг 3 — ✅ сделано (v1):** журнал `.dsh-dev-retro.jsonl` рядом с пакетом;
  `dsh_retro` пишет факт вызова; тест-кит дёргает тул по-настоящему и проверяет ответ.
- **Шаг 4 — открыт:** сводка повторяющихся граблей из журнала → кандидаты в канон
  (раз в N сессий / по запросу «покажи ретро-паттерны»).
- **Шаг 5 — открыт:** section в system-prompt через `system-prompt/assemble` —
  персистентное напоминание Фазы 7 каждому агенту профиля (нужен контракт
  PromptAssembly перед реализацией).
